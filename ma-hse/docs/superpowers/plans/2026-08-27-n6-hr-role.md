# N6_HR Role Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename the dormant `MEDICO` role to `N6_HR`, let `N0_ADMIN`, `N1_CORPORATE`, `N2_PLANT_MANAGER` and `N3_SAFETY` create it (today only N0/N3 can create `MEDICO`, and N2 cannot manage users at all), and give it real navigation + API access to Safety Dashboard, Communications, Actions, Sewo, Occupational Health and Competences — full access to Communications (already granted to `MEDICO`, just never wired into navigation) and Occupational Health (matching `N3_SAFETY`'s current powers), view-only access to Actions, Sewo and Competences (list/detail/export, no create/approve/grant).

**Architecture:** `MEDICO` today is functionally inert — it exists in the `RoleCode` enum and in a handful of permission lists, but appears in zero navigation items and zero API routes for Actions/Sewo/Occupational Health/Competences (Communications is the one exception: it already has full route access, just no nav entry). This plan is a Postgres-native enum value rename (`ALTER TYPE ... RENAME VALUE`, not a drop/recreate — it preserves every existing `UserPlantRole` row referencing the old value) plus additive changes to permission lists, navigation config, and API route guards. No new database tables.

**Tech Stack:** Next.js App Router, Prisma/PostgreSQL, Vitest.

## Global Constraints

- Kill any running `next dev` / `npm run dev:all` process before `npx prisma generate` or `npx prisma migrate dev` (Windows file lock on `query_engine-windows.dll.node`).
- Every route that changes state calls `requirePlantAccess()` first; `N0_ADMIN` and `N1_CORPORATE` bypass the allowed-roles list inside that guard (`lib/rbac/guards.ts`) — never add `N0_ADMIN`/`N1_CORPORATE` explicitly to a route's `allowedRoles` array purely for this reason, they already pass.
- `N6_HR` stays plant-scoped (`PLANT_SCOPED_USER_ROLES`), exactly like `MEDICO` was.
- Terminate the whole plan with `npm run build && npm run test:unit`, both clean, run from `c:\HSE\ma-hse`.

This is a native PostgreSQL 10+ operation: atomic, preserves every existing row's value (a row that read `MEDICO` now reads `N6_HR`), and requires no table rewrite.
